# DLX Sudoku

## Description
A Sudoku game written in C++ that utilizes Donald Knuth's DLX algorithm (Dancing Links) to solve puzzles by transforming them into an exact cover problem. This implementation is based on Knuth's paper, which can be found [here](https://arxiv.org/pdf/cs/0011047). The game features a GUI created with Qt.

![dlx_sudoku](https://github.com/jasonchen17/dlx_sudoku/blob/main/screenshots/dlx_sudoku.png?raw=true)

## Problem and Motivation

Sudoku is a constraint satisfaction problem: each row, column, and 3x3 subgrid must contain the digits 1-9 exactly once. A brute-force backtracking solver works but wastes time exploring invalid branches. Knuth's Algorithm X with Dancing Links (DLX) solves this more efficiently by reformulating Sudoku as an exact cover problem and using a sparse linked-list matrix that supports O(1) cover/uncover operations with backtracking.

## Solution Summary

The solver transforms a 9x9 Sudoku grid into a 729-row by 324-column binary matrix encoding four constraint types. It then builds a doubly-linked sparse matrix (Dancing Links) from that binary matrix and applies Algorithm X -- a recursive, depth-first search with column covering and uncovering -- to find an exact cover. The exact cover maps directly back to a solved Sudoku board.

## Tech Stack

- **Language**: C++17
- **GUI**: Qt (supports Qt5 and Qt6) via Qt Widgets
- **Build**: CMake (minimum 3.5)
- **UI layout**: Qt Designer (`.ui` file with 81 `QLineEdit` widgets for cells)

## Architecture Summary

The project is a single-window Qt application. All logic lives in one class (`MainWindow`) which handles both GUI interaction and the DLX solver. Key data structures:

- `board[9][9]` -- current puzzle state
- `initial_board[9][9]` -- snapshot of generated clues (used to distinguish given vs. user-entered cells)
- `matrix[729][324]` -- binary exact cover matrix
- `Node` struct -- doubly-linked list node with left/right/up/down pointers plus a column header pointer
- `root` -- header node for the Dancing Links structure
- `solution` -- vector of `Node*` representing the selected rows

See [docs/architecture.md](docs/architecture.md) for detailed component descriptions and data flow.

## How It Works

### Exact Cover Formulation

Each of the 729 possible placements (9 values x 9 rows x 9 columns) becomes a row in the binary matrix. The 324 columns encode four constraint groups of 81 columns each:

| Columns   | Constraint | Meaning                                    |
|-----------|------------|--------------------------------------------|
| 0-80      | Cell       | Exactly one value per cell                 |
| 81-161    | Row        | Each value appears once per row            |
| 162-242   | Column     | Each value appears once per column         |
| 243-323   | Subgrid    | Each value appears once per 3x3 subgrid    |

### Dancing Links (DLX)

The binary matrix is converted into a sparse doubly-linked list. Each `1` in the matrix becomes a `Node` linked to its neighbors in four directions and to its column header. The algorithm:

1. If all columns are covered, a solution is found.
2. Choose the column with the fewest nodes (S-heuristic to minimize branching).
3. Cover that column and try each row in it.
4. For each chosen row, cover all columns that row satisfies, then recurse.
5. If recursion fails, uncover (restore links) and try the next row.

Pre-filled cells are handled by finding their corresponding nodes and covering them before the search begins (`cover_unsolved_board`).

### Puzzle Generation

New puzzles are generated by placing 9 random values on the board, solving the resulting board with DLX to get a valid completed grid, then removing cells based on difficulty (Easy: 40, Medium: 50, Hard: 60, Very Hard: 70 cells removed).

## Setup and Build

### Prerequisites

- CMake 3.5+
- Qt5 or Qt6 with the Widgets module
- A C++17-compatible compiler

### Build Steps

```bash
mkdir build && cd build
cmake ..
cmake --build .
```

On macOS this produces `dlx_sudoku.app`. On Linux/Windows it produces the `dlx_sudoku` executable.

### Running

```bash
# macOS
open build/dlx_sudoku.app

# Linux / Windows
./build/dlx_sudoku
```

## Key Engineering Decisions

See [docs/decisions.md](docs/decisions.md) for detailed decision records. Highlights:

- **Single-class architecture** -- all solver and UI logic in `MainWindow` for simplicity given the small codebase.
- **Two-phase matrix construction** -- builds a boolean array first, then converts to linked list, keeping the constraint encoding readable.
- **S-heuristic column selection** -- always picks the column with the fewest remaining nodes to minimize the search tree.

## Limitations

- No input validation on manually entered values (non-numeric or out-of-range input is not rejected).
- Puzzle generation does not guarantee a unique solution; it places random values and removes cells without checking uniqueness.
- Memory management uses raw `new` without corresponding `delete`; nodes allocated during solving are never freed.
- Fixed window size (1024x768) with no responsive layout.
- No undo/redo for user-entered values.

## Future Improvements

- Validate user input to accept only digits 1-9.
- Ensure generated puzzles have a unique solution.
- Replace raw pointers with smart pointers or arena allocation to prevent memory leaks.
- Separate solver logic from the GUI into its own class for testability.
- Add timer and move counter for gameplay tracking.
